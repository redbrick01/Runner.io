# DESIGN.md 적용 계획서

작성일: 2026-05-24

## 1. 목표

현재 Flutter 앱의 기존 구조와 시각 언어를 유지하면서 getdesign.md의 디자인 참고 파일을 선별 적용한다. 전체 앱을 한 브랜드 스타일로 덮어쓰기보다, 화면의 역할에 따라 적합한 디자인 원칙을 부분 적용해 러닝 앱의 완성도, 일관성, 조작성을 높인다.

핵심 방향은 다음과 같다.

- 기본 앱 톤: Apple DESIGN.md
- 러닝 성취/운동 몰입 화면: Nike DESIGN.md
- 지도/영토/장소형 카드 UX: Airbnb DESIGN.md
- 러닝 중 지도 조작/상태 컨트롤: Uber DESIGN.md

## 2. 현재 앱 디자인 진단

현재 앱은 밝은 iOS 스타일 모바일 앱에 가깝다.

- `AppColors`가 iOS 블루 계열 `primary`, 밝은 회색 `background`, 흰색 `surface`, 얇은 `border` 중심으로 구성되어 있다.
- `ThemeData`는 Material 3 기반이며, 버튼과 입력 필드는 16px 라운드, 낮은 elevation, 넓은 터치 영역을 사용한다.
- 주요 화면은 `Scaffold`, `AppBar`, `ListView`, `RefreshIndicator`, private 위젯 분리 패턴을 반복한다.
- 통계/랭킹/히스토리 화면은 카드, 세그먼트 컨트롤, 메트릭 그리드 중심이다.
- 러닝 지도 화면은 Google Map, 커스텀 지도 스타일, 실시간 폴리라인/폴리곤, 지도 위 오버레이 컨트롤이 핵심이다.

따라서 가장 안전한 기본 방향은 Apple 스타일을 기준으로 삼고, 운동성과 지도 UX가 필요한 화면에 Nike, Airbnb, Uber의 요소를 제한적으로 섞는 것이다.

## 3. 적용할 DESIGN.md 우선순위

### 3.1 Apple DESIGN.md

적용 범위: 앱 전체 기본 디자인 시스템

적용 이유:

- 현재 색상, 여백, 카드, 입력 필드, AppBar가 이미 Apple/iOS 계열과 잘 맞는다.
- 과격한 시각 변경 없이 완성도를 끌어올릴 수 있다.
- 로그인, 마이페이지, 분석, 기록, 업적 등 대부분의 일반 화면에 적용하기 쉽다.

적용 항목:

- 타이포그래피 계층 정리
- 페이지별 상단 여백과 리스트 패딩 통일
- 카드 radius, border, shadow 사용 기준 정리
- 입력 필드, 버튼, 탭 컨트롤의 높이/상태 스타일 통일
- 빈 상태, 오류 상태, 로딩 상태의 문구와 아이콘 톤 정리

### 3.2 Nike DESIGN.md

적용 범위: 운동 성취감이 필요한 화면

우선 대상:

- `RunResultPage`
- `AchievementPage`
- 로그인 첫 화면의 브랜드 영역
- 러닝 시작/카운트다운/완료 상태

적용 이유:

- 러닝 앱의 에너지, 기록 달성감, 경쟁성을 강화하기 좋다.
- 현재 앱은 기능은 충분하지만 운동 앱 특유의 강한 성취 표현이 약한 편이다.

적용 항목:

- 기록 완료 화면의 대표 수치 시각적 강조
- 거리, 페이스, 포인트, 고도 등 핵심 숫자의 타이포 대비 강화
- 업적 카드의 배지와 진행률 표현 개선
- CTA 문구와 버튼 위계 정리

주의점:

- 전체 앱을 검정/대문자 중심으로 바꾸지 않는다.
- iOS풍 기본 시스템과 충돌하지 않도록 성취 화면에만 제한 적용한다.

### 3.3 Airbnb DESIGN.md

적용 범위: 지도, 영토, 장소형 정보 화면

우선 대상:

- `TerritoryDetailPage`
- `RunHistoryPage`
- 지도 위 영토 정보 카드
- 경로 미리보기 카드

적용 이유:

- 앱의 영토 점령 개념은 장소/지도/기록 카드 UX와 잘 맞는다.
- 장소 정보, 기여자, 타임라인, 경로 요약을 더 읽기 쉽게 만들 수 있다.

적용 항목:

- 지도 미리보기와 정보 카드 간 간격 정리
- 영토 상세의 메트릭, 기여자, 타임라인 카드 구조 개선
- 히스토리 리스트의 장소형 카드 레이아웃 개선
- 선택 가능한 카드의 터치 피드백과 정보 밀도 조정

주의점:

- 따뜻한 코랄 계열을 앱 전역 색상으로 쓰지 않는다.
- 현재 `AppColors.primary`와 사용자 프로필 색상을 우선 유지한다.

### 3.4 Uber DESIGN.md

적용 범위: 러닝 중 지도 조작 화면

우선 대상:

- `RunningMapPage`
- 지도 하단 러닝 상태 패널
- 시작/일시정지/재개/종료 버튼
- 현재 위치/나침반/카메라 추적 컨트롤

적용 이유:

- 이동 중 지도 UI는 정보가 빠르게 읽혀야 하고, 버튼이 명확해야 한다.
- Uber 스타일의 명확한 조작 패널과 상태 중심 구조는 러닝 중 화면에 참고 가치가 있다.

적용 항목:

- 지도 위 컨트롤의 위치, 크기, 우선순위 정리
- 러닝 중 패널의 상태 표현 강화
- 주요 CTA와 보조 지도 버튼의 시각적 위계 분리
- 한 손 조작을 고려한 하단 중심 배치 검토

주의점:

- Uber식 강한 흑백 톤을 앱 전체에 적용하지 않는다.
- 러닝 중 가독성과 안전한 조작성을 최우선으로 둔다.

## 4. 단계별 실행 계획

### 1단계: 디자인 토큰 정리

대상 파일:

- `lib/app_colors.dart`
- `lib/main.dart`

작업:

- 현재 색상 토큰을 유지하되 역할명을 더 명확히 정리한다.
- 카드, 패널, divider, success, warning 등 필요한 보조 토큰을 추가한다.
- `ThemeData`의 버튼, 입력, AppBar, SnackBar, Dialog 기본 스타일을 통일한다.
- 화면별로 반복되는 radius와 border 사용 기준을 문서화한다.

완료 기준:

- 기존 주요 화면의 색감이 크게 흔들리지 않는다.
- 새 화면이나 컴포넌트가 `AppColors`와 `ThemeData`만으로 기본 톤을 맞출 수 있다.

### 2단계: 공통 UI 패턴 추출

대상 화면:

- `StatisticsPage`
- `RankingPage`
- `PointHistoryPage`
- `RunHistoryPage`
- `MyPage`

작업:

- 반복되는 세그먼트 컨트롤 패턴을 공통 위젯으로 추출한다.
- 반복되는 흰색 카드, 메트릭 카드, 빈 상태 카드를 공통화한다.
- 리스트 padding, 카드 간격, 제목 스타일을 통일한다.
- Apple DESIGN.md 기준으로 조용하고 읽기 쉬운 기본 표면을 만든다.

완료 기준:

- 화면별 구현 중복이 줄어든다.
- 탭/카드/빈 상태가 같은 앱 안의 같은 구성요소처럼 보인다.

### 3단계: 러닝 지도 화면 개선

대상 화면:

- `RunningMapPage`

작업:

- Uber DESIGN.md를 참고해 지도 위 컨트롤의 정보 위계를 재정리한다.
- 러닝 전, 카운트다운, 러닝 중, 일시정지, 종료 중 상태별 패널을 명확히 구분한다.
- 주요 버튼은 하단 중심에 크게 두고, 보조 지도 버튼은 우측 또는 상단에 정리한다.
- 지도 자체는 현재 밝은 커스텀 스타일을 유지하되, 폴리라인/영토 오버레이 가독성을 점검한다.

완료 기준:

- 러닝 중 화면에서 거리, 시간, 페이스, 현재 상태가 즉시 읽힌다.
- 시작/일시정지/종료 조작이 서로 혼동되지 않는다.
- 지도 조작 버튼과 러닝 조작 버튼의 역할이 명확히 분리된다.

### 4단계: 기록/성취 화면 강화

대상 화면:

- `RunResultPage`
- `AchievementPage`
- `StatisticsPage`

작업:

- Nike DESIGN.md를 참고해 기록 완료 화면의 대표 수치를 더 크게 강조한다.
- 업적 카드의 달성/미달성 상태 차이를 명확히 한다.
- 통계 화면은 Apple 기본 톤을 유지하되 핵심 성장 지표에는 더 강한 타이포 대비를 준다.
- 과한 장식보다 숫자, 진행률, 배지의 시각적 명확성을 우선한다.

완료 기준:

- 러닝 완료 후 성취감이 현재보다 명확해진다.
- 기록 수치와 보조 설명의 위계가 한눈에 구분된다.
- 테스트에서 텍스트 overflow가 발생하지 않는다.

### 5단계: 영토/히스토리 화면 정리

대상 화면:

- `TerritoryDetailPage`
- `RunHistoryPage`
- `PointHistoryPage`

작업:

- Airbnb DESIGN.md를 참고해 장소형 카드 레이아웃을 정리한다.
- 지도 미리보기, 메트릭, 타임라인, 기여자 정보를 섹션 단위로 읽기 쉽게 배치한다.
- 리스트 항목의 터치 영역과 요약 정보를 명확히 한다.
- 영토 색상과 사용자 프로필 색상이 카드 안에서 자연스럽게 보이도록 accent 사용 규칙을 정한다.

완료 기준:

- 지도/영토 정보가 기능별로 분리되어 읽힌다.
- 기록 목록에서 상세로 이동할 이유가 명확하게 드러난다.

### 6단계: 검증 및 회귀 방지

작업:

- `flutter analyze` 실행
- 기존 위젯 테스트 실행
- 주요 화면의 작은 화면 폭에서 텍스트 overflow 확인
- 지도 화면의 상태별 수동 확인
- 로그인, 회원가입, 러닝 기록 저장, 통계/랭킹/히스토리 진입 플로우 확인

완료 기준:

- 정적 분석 오류가 없다.
- 기존 테스트가 통과한다.
- 주요 화면에서 레이아웃 깨짐, 텍스트 겹침, 터치 영역 축소가 없다.

## 5. 적용 원칙

- 하나의 브랜드 디자인을 그대로 복제하지 않는다.
- `AppColors.primary`와 현재 앱의 밝은 iOS 기반 톤을 유지한다.
- 화면 역할에 따라 참고 md를 제한 적용한다.
- 지도 화면은 미려함보다 이동 중 가독성과 조작성 우선이다.
- 카드 중첩을 줄이고, 섹션과 카드의 역할을 분리한다.
- 텍스트가 긴 한국어 환경에서 overflow가 나지 않도록 `maxLines`, `overflow`, 반응형 배치를 우선 고려한다.
- 디자인 개선과 비즈니스 로직 변경을 같은 PR 또는 커밋에 섞지 않는다.

## 6. 추천 적용 순서

1. Apple DESIGN.md 기준으로 공통 토큰과 ThemeData 정리
2. 공통 카드/세그먼트/빈 상태 위젯 추출
3. RunningMapPage의 러닝 상태 패널과 CTA 정리
4. RunResultPage와 AchievementPage의 성취 표현 강화
5. TerritoryDetailPage와 RunHistoryPage의 지도/장소형 카드 정리
6. 전체 테스트와 화면 검수

## 7. 예상 리스크

- 디자인 토큰 정리 중 기존 테스트의 색상/텍스트 탐색 조건이 깨질 수 있다.
- `RunningMapPage`는 상태와 플랫폼 연동이 많아 UI 리팩터링 시 회귀 위험이 높다.
- 카드 radius, shadow, padding을 한 번에 바꾸면 앱 인상이 크게 달라질 수 있다.
- 한국어 텍스트와 숫자 단위가 긴 화면에서 작은 기기 overflow가 발생할 수 있다.

대응:

- 지도 화면은 가장 작은 단위로 나누어 변경한다.
- 공통 위젯 추출은 먼저 통계/랭킹처럼 위험이 낮은 화면에서 검증한다.
- 색상 변경은 기존 `AppColors` 이름을 보존하면서 점진적으로 확장한다.
- 각 단계마다 `flutter analyze`와 관련 위젯 테스트를 실행한다.

## 8. 최종 산출물

- 정리된 디자인 토큰과 앱 테마
- 반복 UI를 줄인 공통 컴포넌트
- 지도 화면의 명확한 러닝 상태 패널
- 더 강한 성취감을 주는 러닝 결과/업적 화면
- 더 읽기 쉬운 영토/기록 카드
- 단계별 테스트 결과 기록
